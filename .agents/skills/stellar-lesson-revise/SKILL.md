# 课程网页修订与审核

先读 AGENTS.md 和目标课程源码。需要教材时按 textbooks/pdf/README.md 补齐并读取；需要格式、构建或检查命令时查 tools/FORMAT.md。只进入用户指定的阶段：分析、修改、PR 交付、审核或收尾。直接收到明确修改方案时进入修改；只审核或收尾时不重新选方案、建分支或修改作者文件。缺少前提时只说明该阶段缺什么。

## 分析与修改

1. 明确本轮课程、反馈或具体修改、处理人与不同的审核人。来自飞书时按“反馈对象=课程网站且处理状态为未开始、修改中或待审核”筛选，并限定本轮范围；“已停滞”及原因单独列出，由负责同学决定是否恢复，历史空状态单独核实。以课程 ID、更新日期、位置和内容指纹定位，兼容旧 version；比较当前内容，识别重复、已修复或教材修订事项。教材 PDF 修订交助教。
2. 未选定方案时给出证据、首选改法、影响和实质取舍，等负责同学选择；分析本身不写处理状态。已有明确方案直接实施，不重复要求助教批准。科学判断按 AGENTS；不把反馈或模型解释当教材证据。
3. 修改前检查工作区、分支及 origin，保留已有工作。新任务从最新 origin/main 建工作分支；已有分支同步 main 后继续。影响科学含义或可能丢失工作的冲突交同学判断。选定范围并分派后可写“修改中”。
4. 修改 lessons/，保持未变内容的稳定 ID，更新内部 version 和日期，重建对应网页。版本及技术要求见 FORMAT；脱敏修改依据记在 PR，记录级处理结论记在飞书，不给学生正文添加维护日志。按下表验证，并请处理同学亲自查看实际修改。

## 按影响范围验证

所有课程修改都执行源码/HTML 一致性检查和现有工具测试；浏览器检查按影响扩大，不以自动检查代替教学判断。

| 改动 | 核实与验收范围 |
| --- | --- |
| 错字、局部措辞或显示 | 对应段落、上下文和实际显示；涉及物理含义则按下一类处理，不重写整课提纲。 |
| 概念、公式、题目或解释结构 | 原版依据、适用条件、关联正文和所有受影响题目/解析；实际检查相关公式、答题与窄屏显示。按需引用制作 skill 的“知识组织与表达”，不执行整套新建课程验收。 |
| 共用样式、交互或构建器 | 全站重建、工具测试及相关浏览器回归；检查受影响课程，涉及控件时覆盖键盘、焦点、重试和文字放大。 |

结构变化时才更新受影响部分的源码提纲和知识覆盖。未改到的课程只记录影响，不擅自扩展修改范围。

## PR、审核与发布

1. 处理同学授权交付后，审查差异和脱敏，将本轮源码及输出提交到工作分支、推送并创建面向 main 的 PR，指定另一位同学。按 PR 模板写依据、改法和验证局限，回填 PR链接及“待审核”。
2. 审核人使用本人账号和独立会话核对 PR 当前提交、教材依据及实际页面。先 check 已提交输出，不能先重建掩盖遗漏；按上表核实影响。只请求审核时给结论，未经授权不提交批准或合并。需要修改则回到“修改中”，作者更新后重审。
3. 审核同学明确授权合并后，确认提交未变、审核有效及远端实际配置的必需检查满足再合并，不绕过保护。跟踪对应合并提交的 Pages 部署，确认线上内容和实际效果后回填。没有页面变更的结论型处理走下节，不要求制造 PR 或部署。

## 反馈状态与关闭

“处理状态”表示工作进度：未开始 → 修改中 → 待审核 → 已完成，退回则回到修改中。“已停滞”表示明确决定暂时不处理；原因与处理结论写入“处理说明”，不再维护“是否已解决”字段。

- 已修复：本次或已有修订的线上结果核实通过后标为“已完成”，记录对应版本或 PR。
- 不成立、重复：由审核同学确认后标为“已完成”，处理说明写结论、理由、证据和关联记录。不成立项写清“无需修复”；重复项关联原记录，原问题继续按原记录的实际进度处理，不把关闭重复记录说成问题已修复。
- 暂时不处理：明确决定暂停或由审核同学确认暂不采纳时，标为“已停滞”，记录原因及已经明确的恢复条件。重新纳入工作时，由负责同学确认后改回实际阶段。
- 证据不足、发布失败或未验收：保留进行中的真实阶段，说明缺口；Agent 不因拿不准而自行完成或停滞，疑难交助教。明确决定暂时不处理后才转“已停滞”。

按 record_id 写回前重读记录，只更新 AGENTS 允许的五列中本轮变化的字段，保留他人说明和原始反馈。写回失败保存待重试结论；重试前核对当前状态，不重复已成功操作。收尾报告内容验证、发布/关闭依据和飞书写回结果；已授权的同批收尾持续完成。学生任务结束后不自动提议修改 skill，遇到流程障碍记在正常处理记录中供助教复盘。
