# 制作恒星物理课件

使用项目 `AGENTS.md` 和 `tools/FORMAT.md`。已有课件的反馈修订使用另一 skill；不要重做整个课程系统。

1. 明确教材范围和学习目标。学生基础优先采用教师指定值，其次采用 AGENTS.md 的当前约定；两者均缺失时采用适合本科基础课的深度并说明假设；缺少教材范围时只问这一项，不自行决定正式课表。
2. 查 `mapping/catalog.md` 和对应卷表，从真实入口读取 MinerU 正文。候选对应只是导航，必须读双方正文。译文用于术语与理解，不作为独立证据。核对关键公式、数字、图表与差异判断的拆分 PDF；遇边界错误查整卷原件。不能确认的具体说法不进入已核实讲解，记录缺口。
3. 在对应表中仅将本次确认的具体范围记为已核实，注明小节、印刷页码、拆分 PDF 页序和核实内容；不升级整章其他候选。教材输入不修改。
4. 使用 `lessons/<ID>.md`，遵守 FORMAT。按下文“知识组织与表达”组织学生自主学习：先说明本课主题、核心知识和相互关系，再依概念所需的前置知识展开解释，按教学需要安排图表观察与参数操作，用必要公式建立定量关系，并指引阅读教材具体小节，将 Quiz 集中在章末。主线连续下拉阅读，不提供步骤切换。主线依据 Volume1–3，Ref 中更好或更新的解释放入可点击 details 知识卡片，不写两本书怎样互补的教学管理说明。已有辐射/热统基础的学生应保留定量关系、推导入口和适用边界。Quiz 默认单选和判断，条件充分，只有一个正确选择，解析说明常见误解并指向正文块。
5. 不联网搜索科学进展。模型已有知识仅触发“可能过时、尚未核查”；写清待核查原说法的位置、关键词、适合查阅的来源类型与提交要求。不要凭记忆宣布某任务取消、已发布某数据或解决某争议；不要编造论文或链接。Ref 已有充分解释时用知识卡片解决；仍无解释且有教学价值的缺口才设开放调研。不要把“可能过时”强行转换成每节必有的问题。
6. 生成原创教学解释与原创示意图，公开输出不含教材全文/截图/长摘录/本地路径。复用符合物理问题的活动；需要新的直观解释时可扩展组件，不让现有模板限制内容。数字曲线与示意曲线必须明确区分，模型的假设、归一化、单位和非观测性质要在图旁说明。
7. 执行 `./tools/course build <ID>`、`./tools/course check`。浏览器检查图文与公式、至少一个交互、全部答案和解析、飞书反馈入口、窄屏及在线操作。纯静态检查不代表教学正确或视觉通过。
8. 交付源文件、HTML、核实范围和未解决项。课程创建不隐含 Git 提交、推送或发布授权。

一个独立 HTML 必须包含核心资源；公式使用原生 MathML，格式见 FORMAT，不留下未渲染 LaTeX。进展任务的外部参考链接可联网访问，但学习与判题不得依赖它们。

页面面向 GitHub Pages 在线自习，取消下载提示、装饰性英文、操作口号和题数宣传。反馈问卷 URL 位于 tools/feedback.json；未完成飞书授权及实际提交核验时，不声称已能收集反馈。不得在网页嵌入飞书访问密钥。

## 知识组织与表达

课程标题和小节标题直接写物理主题或准确的概念名称，使学生从标题判断内容。避免含糊的问题、悬念和口号。例如，涉及相应内容时可用“光度、辐射通量与星等”；“看到的亮代表什么”指向不清。标题须与实际教材范围一致。

开头用简短段落交代本课研究什么、为什么需要这些知识，并列出本课涉及的核心知识点。随后说明知识点之间的关系和讲解顺序，使学生知道哪些概念提供基础、哪些关系用于推导、哪些内容用于解释或应用。不要把概念名称清单当作整堂课的讲解。

每个知识点先用直白的语言说明含义及它解决的具体问题，再结合需要给出例子、图示、公式和推导。说明本节如何承接前文、所得结果如何用于后文；这些关系应自然写进正文，不必机械重复固定栏目。必要的新术语首次出现时解释，公式说明符号、单位、物理含义和适用条件。依据教师指定的基础保留应有深度。

交互围绕正在解释的物理关系安排，交代改变什么量、观察什么变化，以及变化如何帮助理解该关系。是否先观察再解释由具体知识点决定。核心概念和必要联系写在连续阅读的正文中；补充推导与 Ref 解释放折叠卡片。

正文和答题解析遵守全局 AGENTS.md 的沟通原则：一个段落讲清一个主要意思，用具体、准确、连贯的表达。列表用于确有并列或顺序的内容。删去装饰性文字、套话、自问自答、刻意对比和生造标签，同时保留必要解释。

交付前从学生角度通读：仅看标题能否判断主题；读开头能否说出核心知识与学习目的；读正文能否解释各概念及其关系、说明为什么按此顺序讲解；公式和交互是否得到解释。把无法回答的位置改清楚。构建和显示检查通过后，仍需完成这项教学检查。

## 制作与验收

写正文前，在课程源码的 HTML 注释中维护简短编写提纲，列出核心知识、前置知识及本节结果在后文的用途。先检查概念是否突然出现、解释是否重复、必要联系是否缺失，再安排正文和交互。学生开头读到自然的课程介绍；编写提纲不在页面显示。

每个交互说明改变的量、观察的量和需要理解的物理关系，验收时实际操作并核对现象与解释。交互数量由内容决定。必要的概念解释不能只藏在活动或折叠卡片中。

章末解析说明正确答案的推理依据，并指出各错误选项的具体误解，关联正文概念、公式或适用条件。验证答错后可更改选项并重新提交。按核心理解的需要使用与正文例子不同的情境，检验能否应用已讲的关系，保持题目条件充分。

完成后逐项核对核心知识：正文位置、前置解释、前后关系、需要检验的理解及对应题目。将检查结论记入本次验收材料，不在学生正文放教学管理表格。题目数和交互数不能代替覆盖检查。

浏览器验收补充键盘完成交互与答题、焦点可见、文字放大后的内容可读性，以及图表是否有颜色以外的标识。记录实际检查范围和发现的问题；只通过自动检查时，不声称人工或学生试读通过。
