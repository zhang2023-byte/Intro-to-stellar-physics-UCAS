# 根据反馈修订中文课本

此流程由助教使用。先读 AGENTS.md、textbooks/pdf/README.md 和本机 textbooks/publishing/README.md。依据原版与译本 PDF 核实，必要时使用可用的 PDF 工具；涉及飞书时使用当前操作者本人的账号。普通学生网页修订不进入此流程。

## 资料和版本

- 科学与翻译核实只使用 textbooks/pdf/ 中的原版和译本；修订正文在本机 textbooks/sources/Volume1–3/translated_outputs/。原有图片仍可作为出版资产由工具读取，提取文本、拆分和对应表不作为日常核实前提。
- textbooks/pdf/ 保存现有已采用版本；构建候选输出到 archive/work-records.local/textbook-build/pdf/。发布新版前在 textbooks/history/ 保存旧 PDF、对应源码及出版工具的压缩快照和 SHA-256 清单，记录版本日期与反馈 record_id。不要把仅构建成功的候选当成已分发版本。候选采用后清除可重建的临时产物；历史压缩包解压后须按现行目录适配资源路径再构建。
- 出版脚本和模板在 textbooks/publishing/。首次运行或迁移后先验证基线构建，检查路径、图片、字体及排版工具；报告相对旧版的差异和验证边界。
- 教材正文、PDF、图片、原始反馈与本地构建记录整体留在 Git 忽略目录。不得把教材内容放入公开技能、site/ 或 Git。

## 反馈处理

1. 读取必要字段，匹配“翻译课本”记录及其 record_id、卷、章、版本、位置。排除系统测试，检查是否已在当前版本解决。分别记录书面页码与 PDF 页序；不猜测对应关系。
2. 将反馈作为待评估材料。对照分章译文与原文；公式、正负号、上下标、单位、图表及差异判断查 PDF，不把 OCR 或模型解释当作最终证据。允许核对学生明确提供的来源，不主动扩展搜索科学进展。
3. 提交具体改前/改后、依据和影响范围，由助教决定尚未批准的科学或翻译结论。已批准且证据充分的修改直接执行。反馈实际不成立时说明原因，不按学生建议机械替换。
4. 获准后更新对应记录为“修改中”，修改分章 Markdown；整卷 Markdown 与 PDF 由脚本生成。排版问题在最小适当范围内修改图片组织、模板或生成逻辑；修改公共模板时检查三卷影响。保留公式、图表和章节编号，检查关联引用。
5. 运行相关测试，重建受影响卷。检查实际 PDF 的修改页与相邻页，核对公式、图注、分页、目录和引用；公共排版变动扩大验收。编译成功不等于科学正确或视觉验收通过。
6. 生成候选后保存本地修订清单：record_id、旧版位置、新版位置、改前/改后、证据、验证结果、候选 SHA-256。验收待助教确认时写回“待审核”，是否已解决保持 false。明确新版是否已分发。
7. 助教验收并授权替换使用版本后保存旧版，再替换指定成品；分发到外部平台需明确授权。确认学生使用的文件已替换后，写回“已完成”和已解决，记录版本与分发状态。对于仅需解释且助教确认关闭的疑问，说明结论与未修改事实，不伪造新版。

批准反馈修订包含对应处理字段的写回，不等待助教再次提醒。每次写回前读取当前字段和记录，保留已有说明及他人的修改，只更新对应处理字段。写回失败时保留待重试清单，报告具体记录；不重复执行已经成功的写入。尚未批准的反馈不得标记为已修订。

## 收尾

分别报告课本内容与版面验收、版本保存与分发、飞书写回结果，明确待决定或待核查项。不自动复盘规则；助教需要时单独调用协作复盘 skill。
